# Agent 工作流排障笔记

> 关键词：响应体超限、工具层不稳定、Python f-string JS 模板、数据截断

## 任务背景

为《天幕红尘》生成深度分析 + 交互式思维导图。原始文件 4 份，总计数万字。

## 遇到的问题与根因

### 1. 连续 unknown

**现象**：连续 `unknown` 错误，文件写入失败。

**根因**：单次响应体超限。Agent 在一次回复里携带了过多上下文（历史说明、思考过程、工具指令），导致整轮输出过大，工具调用被截断。

**解决**：把"生成完整文件"改成"骨架 + 占位符 + 分段替换"。每轮只做一件事，每件事只写一个文件的最小单元。

---

### 2. replace_in_file 偶尔可行，连续多轮后失效

**现象**：`replace_in_file` 第一次成功，但连续多次 patch 后也开始失败。

**根因**：连续编辑累计上下文，导致响应体再次超限。

**解决**：同样遵守"极限单操作"原则——一次只替换一个标记，替换成功后立即停，不连续操作。

---

### 3. Python 脚本中文编码问题

**现象**：PowerShell 执行 `python -c "中文内容"` 时报错。

**根因**：PowerShell 对中文内联脚本处理有编码问题。

**解决**：用 `write_to_file` 写 `.py` 文件，再通过 `& "path/to/python.exe" "script.py"` 执行。**不要**用 `-c` 参数传中文代码。

---

### 4. Python f-string 嵌 JS 模板导致 JSON 截断

**现象**：生成的 HTML 思维导图空白，JS 里只有 6 个顶层节点，children 全部丢失。

**根因**：Python f-string 会把所有单花括号 `{}` 当作变量插值。JS 对象字面量 `{...}` 必须写成 `{{...}}`，但处理时漏掉了一个 `{`，JSON 在第一个 `{` 处被截断。

**错误示例**：
```python
html = f"const DATA={json.dumps(data)};"  # f-string 把 { 当插值符，JSON 被截断
```

**正确做法**：不要在 f-string 里直接嵌 JS 模板。

- **方案 A**（推荐）：JS 模板写成普通字符串，json 数据单独写文件再读进来拼接
- **方案 B**：用 `.format()` 或 `%` 格式化，或 `string.Template`
- **方案 C**（最稳）：三步写文件——①写 JS 数据文件 ②写 HTML 模板文件 ③合并

---

## 核心经验总结

| 问题 | 根因 | 稳定做法 |
|------|------|----------|
| Agent 写大文件失败 | 响应体超限 | 骨架 + 占位符替换，或 Agent 只吐内容外部写入 |
| 连续 unknown | 工具层不稳定 | 极限单操作，失败只重试当前最小单元 |
| PowerShell 中文脚本失败 | 编码问题 | 写 .py 文件再执行，不用 -c |
| HTML 里 JSON 被截断 | f-string 干扰 JS {} | JS 模板和数据分离写，不要在 f-string 里嵌 JS |

## 通用原则

1. **不要让 Agent 一次做完**。大任务拆成骨架 → 分段填充 → 验证 → 下一段。
2. **不要在 f-string 里嵌含 {} 的内容**。包括 JS、JSON、正则表达式。
3. **不要连续多轮编辑同一个文件**。每轮只做一件事，成功后立即停。
4. **Python 脚本优先**。涉及复杂字符串拼接时，用 Python 脚本比 Agent 直接写更可靠。
