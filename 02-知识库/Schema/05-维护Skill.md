# 知识库维护 Skill

> 知识库不是建完就完事的。定期维护比新增内容更重要——发现矛盾比积累事实更有价值。

## 触发时机

- **手动触发**：当你说「维护一下知识库」「检查一下维基」
- **被动触发**：每次回答问题时，主动标记「这页很久没更新了」
- **定期**：建议每 1-2 周做一次全面检查

## 检查清单（按优先级）

### 🔴 1. 矛盾检测（最重要）

**目标**：发现实体页之间的逻辑冲突

**检查方法**：
- 对每个实体页，扫描「我的理解」区和「矛盾/争议」区
- 比对同一概念在不同实体页中的定义是否一致
- 标记：`[[实体A]]` 说 X，但 `[[实体B]]` 说 Y

**发现的矛盾**：
- ✅ 已有矛盾记录 → 检查「我的判断」是否有更新
- ❌ 没有矛盾记录 → 立即建议创建 `Schema/02-矛盾记录Schema.md`

**示例输出**：
```
🚨 矛盾检测结果：

页面 [[岩土工程AI辅助写作系统]] 说：
  「PDF批量测试发现问题：表格数据提取失败」
  
但 [[岩土工程AI写作模板引擎]] 说：
  「表格提取功能已升级完成」
  
→ 建议：更新 [[岩土工程AI辅助写作系统]] 中的描述，标记为已解决
```

---

### 🟠 2. 过时信息检测

**目标**：发现内容落后于现实的实体页

**检查标准**：
- 实体页的 `updated` 日期 > 30 天，且最近有相关活动（日记提到、项目有进展）
- 项目状态标签（`🔒稳定 / ⚠️待验证 / 🌿成长`）与实际情况不符
- 日记或笔记中提到了该实体，但实体页没有更新

**操作**：
1. 列出所有超过 30 天未更新的实体页
2. 对照日记和笔记，标记哪些需要更新
3. 生成更新建议清单

**示例输出**：
```
📅 过时信息检测结果（更新 > 30 天）：

⚠️ [[岩土工程AI辅助写作系统]] - 最后更新：2026-03-21（46天前）
   日记 2026-03-28 提到：「EvoMap 节点保活自动化持续运行」
   → 建议：在实体页补充 EvoMap 节点状态

⚠️ [[EvoMap]] - 最后更新：2026-03-31（36天前）
   → 需要更新当前节点状态
```

---

### 🟡 3. 孤立页面检测

**目标**：找出没有被任何其他页面引用的实体页

**检查方法**：
- 扫描所有实体页的 `cross_refs` 和正文中的 `[[wikilinks]]`
- 没有任何页面引用 → 孤立页面
- 只有单向引用（被引用但无出链）→ 弱孤立

**操作**：
- 孤立页面 → 主动补充 `cross_refs` 或在相关主题索引中添加链接
- 如果该页面确实不重要 → 建议归档到 `杂项/归档/`

**示例输出**：
```
🔗 孤立页面检测结果：

⚠️ 弱孤立页面：
   - [[某概念]] - 被 [[主题索引]] 引用，但本身没有出链
   → 建议：在该页面补充「相关实体」或「应用场景」

❌ 完全孤立页面（无入链无出链）：
   - [[某临时笔记]] - 长期孤立，建议归档或删除
```

---

### 🔵 4. 断链检测

**目标**：发现指向不存在页面的 wikilinks

**检查方法**：
- 扫描所有页面中的 `[[页面名]]` 格式链接
- 验证目标页面是否存在
- 特别检查：重命名页面后，原链接是否失效

**操作**：
- 断链 → 修复链接或标记为「待创建」
- 待创建 → 询问是否需要立即创建

**示例输出**：
```
🔗 断链检测结果：

⚠️ [[待创建页面]] - 被引用但不存在
   来源：[[主题索引-岩土工程]] 提到「参考 [[待创建页面]]」
   → 建议：创建该页面，或修正为已有页面

❌ 断链：
   - [[旧项目名]] → 已改名为 [[新项目名]]
   → 建议：更新所有引用
```

---

### 🟢 5. 主题索引一致性检查

**目标**：确保主题索引反映了实际的实体页状态

**检查内容**：
- 主题索引中列出的实体页是否都存在
- 新增的实体页是否已加入相关主题索引
- 知识树结构是否与实际子主题匹配

```markdown
- 实体页总数：N
- 主题索引：N
- 上次维护：YYYY-MM-DD

## 发现与处理

### 矛盾检测
- 发现新矛盾：N 条 → 已建议创建矛盾记录
- 已有矛盾更新：N 条

### 过时信息
- 需要更新的页面：N 条
- 已更新：N 条

### 孤立/断链
- 孤立页面：N 条 → 已处理/待处理
- 断链：N 条 → 已修复/待修复

## 行动清单
- [ ] 更新 [[页面名]] - 原因
- [ ] 创建矛盾记录 [[矛盾标题]]
- [ ] 修复断链 [[来源]] → [[目标]]

---

_由 Jarvis 生成，下次维护建议：YYYY-MM-DD_
```

---

## 执行原则

1. **不要过度维护** — 检查完立即停止，不要陷入无休止的整理
2. **优先矛盾** — 发现矛盾比更新格式更有价值
3. **小批量处理** — 每次维护处理不超过 5 个问题，其余排队
4. **记录结论** — 所有维护动作都要记录到报告中
